## Quality-level breakdown

| QUALITY | PASS / 21 | %  | Lone failure mode |
|---------|-----------|----|-------------------|
| draft   | 21        | 100 % | none |
| standard | 8        | 38 % | 13× hard ``hausdorff_relative`` (extrusion fastpath synthetic surface diverges 8-73 % from curved input STLs) |
| fine    | 0         | 0 % | all hard ``max_non_orthogonality`` (no tet+BL bump for fine) |

The standard-quality drop from the initial "18/21" report is because the
U-15 audit revealed 17/21 cases use the extrusion fastpath (not pytetwild
as previously thought).  The extrusion fastpath sweeps a 2D cross-section
along an axis — a synthetic shape that diverges from curved input STLs by
8-73 % Hausdorff distance.  At draft the cap is 10 % (relaxed); at
standard 5 % (strict), most extrusion outputs fail.

Extending standard coverage requires improving extrusion fastpath
fidelity or routing curved inputs through a different self-impl path —
multi-week scope.  draft remains the bench default and matches CLI
default users invoke.

Draft is the bench default and matches the CLI default in ``cli/main.py``.
The standard/fine failures stem entirely from **input STL quality**:
extreme_1017017, hard_100030, hard_1004826 each have 55+ self-intersections
in the source STL.  pytetwild's envelope wrap of the broken input
produces an output surface whose Hausdorff distance to the original
exceeds 5 % bbox diagonal — a real geometric divergence, not a pipeline
defect.  Fixing requires either Boolean-union-style multi-shell repair
in the preprocessor or a sliver-aware tet generator — multi-week scope.
