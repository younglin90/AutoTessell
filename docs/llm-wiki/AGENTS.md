# 위키 유지보수 지침

이 디렉터리는 AutoTessell을 위한 LLM 소유의 합성 지식 계층이다. 저장소 코드, 테스트, 벤치 결과, 명세, 문헌 노트, Git 이력은 원본 소스다. 위키를 갱신한다는 이유로 원본을 수정하지 않는다.

## 근거 우선순위

1. 실행 코드와 테스트는 현재 작업트리가 실제로 하는 일을 보여준다.
2. 영구 게이트와 canonical benchmark는 실측 합격 계약을 보여준다.
3. 통합 개발 계획과 evidence matrix는 카드 순서와 문헌 근거를 보여준다.
4. `ROADMAP.md`, `SPEC.md`와 일반 설명문은 제품 의도를 보여주지만 코드보다 늦을 수 있다.
5. 이 위키는 위 계층을 합성할 뿐 어느 것도 덮어쓰지 않는다.

## 필수 메타데이터

지식 페이지의 YAML frontmatter에는 `type`, `status`, `updated`, `stability`, `source_paths`, `tags`를 둔다. `stability` 값은 다음 중 하나다.

- `contract`: 현재 테스트나 영구 게이트가 강제
- `implemented`: 코드에서 확인되지만 제품 연결은 별도 확인 필요
- `working-tree`: 미커밋 코드에서 관찰
- `measured`: 명시된 벤치나 evidence 원장이 뒷받침
- `planned`: 계획에는 있지만 미구현
- `historical`: 변화 과정을 설명하기 위한 과거 상태

## 작업 종류

### Ingest

변경된 원본을 읽고 영향을 받는 최소 문서만 고친다. wikilink를 추가·수리하고, 문서 구성이 바뀌면 `index.md`를 갱신하며, `log.md`에 날짜가 있는 항목을 덧붙인다. 계획을 구현 사실로 조용히 바꾸면 안 된다.

### Query

먼저 위키에서 답을 찾되, 변하기 쉬운 사실과 줄 단위 주장은 원본으로 재확인한다. 질문이 빈 지식을 드러내면 해당 문서를 보충하고 작업 기록을 남긴다.

### Lint

깨진 wikilink, 고립 문서, 존재하지 않는 `source_paths`, 중복 제목, 누락 메타데이터, 낡은 스냅샷 주장, 근거 없는 구현 설명을 검사한다. 불일치는 매끈하게 지우지 말고 [[Contradictions and Open Questions|불일치 원장]]에 남긴다.

## 문체와 안전

사용자용 위키 본문은 한국어로 쓴다. 코드 이름·경로·수식·논문 고유명은 원문을 유지한다. 표면 보존은 최상위 불변식이다. surface hash, face-set, area, wall deviation, envelope 등의 가드가 없는 표면 이동을 안전하다고 표현하지 않는다. 병렬 메커니즘은 결정론적 정확성 게이트가 마련된 뒤 마지막 단계에서 다룬다.
