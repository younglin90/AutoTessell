# CARD BETA2285_VVV9K8_HARDEN_MONOTONE (beta2285) — VVV9K main_loop monotone hardening

**target_engine**: tet
**모티프**: Klingner & Shewchuk 2008 §3.5 Algorithm 1 — priority-queue main loop with strict per-iteration monotone guard + early-exit on stagnation (R198 hardening pattern adapted to helper-OFF monitoring).

## 이론적 근거 (≤30줄)

- **문제 정의**: VVV9K4 `_priority_queue_main_loop` is helper-only (gate `_VVV9K4_MAIN_LOOP=False`). When future cards activate it, **per-iteration monotone safety is required**:
  - Let q_pre = worst element before iter i, q_post = worst element after iter i.
  - **Monotone invariant**: q_post ≥ q_pre - ε (ε=1e-9 floor).
  - Klingner §3.5 Alg 1 mandates "reject the operation if it does not improve the worst element" — current skeleton trusts `attempt_improvement.success`+`delta` without explicit pre/post worst comparison at the loop level.
- **본 카드의 핵심 아이디어** (helper-only hardening, gate-OFF):
  1. After each `attempt_improvement` call, capture `delta = res.get("delta", 0.0)`; if `success=True` but `delta <= 1e-9`, mark as **rejected** (n_rejected++ ; n_improved untouched, total_delta unchanged).
  2. Maintain a **stagnation counter** `n_no_improve` — increment on reject/no-success, reset on real improvement; **early-exit** when `n_no_improve ≥ K` (K=8, Klingner §3.5 default).
  3. Add `n_rejected`, `early_exit_reason` to return as 6th/7th tuple elements (extension is backward-compatible since gate OFF → no caller).
- **레퍼런스**: Klingner & Shewchuk 2008 §3.5 Alg 1 (Stellar); R198 (VVV9H7) hardening pattern (per-op monotone revert).
- **혁신성 평가**: novelty=1 (R198 pattern adapted), rigor=2 (explicit invariant + early-exit constant K), impact=2 (prevents future regression at main_loop activation). 합 = 5 (권장 충족).

## 변경

- 파일: `core/generator/native_tet/stellar.py` (단일 파일)

- 핵심 변경 (≤80줄):

  2. Per-iteration: after `attempt_improvement`, if `success=True and delta > 1e-9`: `n_improved++`, `n_no_improve=0`; elif `success=True and delta <= 1e-9`: `n_rejected++`, `n_no_improve++`; else: `n_no_improve++`.
