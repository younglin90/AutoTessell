# CARD BETA2279_VVV9K2_PRIORITY_QUEUE_POP (beta2279) — fTetWild §3.3 priority-queue pop helper

**target_engine**: tet
**모티프**: fTetWild §3.3 Algorithm 2 / Klingner & Shewchuk 2008 §3 — incremental worst-first heap pop

## 이론적 근거 (≤30줄)

- **문제 정의**: fTetWild §3.3 의 mesh-improvement loop 는 worst tet 를
  반복적으로 처리한다. VVV9K1 은 offline `_priority_queue_init` 를 도입했지만,
  매 iteration 마다 전체 heap 을 rebuild 하면 O(N log N) — chunked path 에서
  100k tets × 10 cycle = 1e7 ops 가 hot-spot 이 된다.
- **본 카드의 핵심 아이디어**:
  1. `_priority_queue_pop_worst(heap, k=1)` — 이미 heapify 된 heap 객체를
     인자로 받아 `heapq.heappop` 을 k 회 수행.
  2. heap 은 list[tuple[float, int]] (quality, tet_index) — VVV9K1 과 호환.
  3. mesh / quality array 는 건드리지 않는다 — 인덱스 list 만 반환.
  4. NaN-safe: pop 한 (q, idx) 의 q != q 일 경우 skip 후 다음 pop.
  5. heap 이 비면 짧은 list 반환 (graceful).
- **VVV9K1 과의 차이**: K1 은 array → indices (one-shot). K2 는 heap → indices
  (incremental); VVV9K3+ 가 update / re-push 를 추가해 fTetWild §3.3 의 amortized
  O(log N) 루프를 완성한다.
- **레퍼런스**: Hu 2020 fTetWild §3.3 Alg 2, Klingner 2008 §3, CPython heapq §8.5.
- **혁신성 평가**: novelty 1 / rigor 2 / impact 2 → 5 (skeleton 으로 적정).

## 변경

- 파일: `core/generator/native_tet/stellar.py` (단일)
- 함수: 신규 `_priority_queue_pop_worst` (VVV9K1 helper 직후, line ~2282)
- 핵심 변경 (≤80줄):
  1. `_VVV9K2_PRIORITY_QUEUE_POP: bool = False` (default OFF flag, no caller).
  2. `def _priority_queue_pop_worst(heap, k=1) -> list[int]:`
     - `if not heap or k <= 0: return []`
     - `out: list[int] = []`
     - `for _ in range(min(k, len(heap))):`
         - `q, idx = heapq.heappop(heap)`
         - `if q != q: continue` (NaN guard)
         - `out.append(int(idx))`
     - `return out`
  3. caller 추가 없음 (VVV9K3 가 wire-in 예정).
- 단조 가드: caller 없음 → mesh / quality 무변경. 회귀 0 자명.
